# best

A Rust CLI for encrypting individual files with the interoperable **age v1**
format. Passwords and X25519 public recipients are supported. File processing
streams with bounded memory, originals are preserved, and existing destinations
are never overwritten.

Built with **Rust 1.98.1**, the latest stable release verified on 2026-09-05.
The exact toolchain and dependency lockfile are committed for repeatable builds.

## Quick start on Windows

Open PowerShell in this folder and run `build.bat` to create `dist\best.exe`.
The supplied `best.bat` launches it; run `test.bat` to check the project.
Compiled executables and Cargo build artifacts are excluded from this repository.

```powershell
# Encrypt: enter and confirm a long password at the hidden terminal prompt.
.\best.bat encrypt "C:\path\report.pdf"

# Decrypt to a NEW path. The original report.pdf still exists.
.\best.bat decrypt "C:\path\report.pdf.age" -o "C:\path\restored.pdf"

# Fully authenticate a file without saving any plaintext.
.\best.bat verify "C:\path\report.pdf.age"

.\best.bat --help
```

Encryption appends `.age` by default. Decryption strips a final `.age`, or uses
`--output`. If that path already exists, choose another path. There is no force
overwrite or delete-original switch. `--quiet` suppresses success diagnostics.

## Public-key encryption

```powershell
# Private identity goes to disk with restrictive permissions.
# Only the public recipient is printed; it is safe to share.
$recipient = .\best.bat keygen -o personal.key
.\best.bat encrypt report.pdf -r $recipient
.\best.bat decrypt report.pdf.age -i personal.key -o restored.pdf
.\best.bat verify report.pdf.age -i personal.key
.\best.bat recipients -i personal.key
```

Repeat `-r` for multiple recipients: any one of their private identities can
decrypt. Up to 64 unique recipients are supported. Decryption accepts up to four
`-i` files, each containing up to 32 X25519 identities, with blank lines and `#`
comments. The program creates **unencrypted private identity files**, like
`age-keygen`: store them securely, back them up separately, and never share them.
For password-protected storage without a separate key, use password mode.

## Automation

```powershell
.\best.bat encrypt report.pdf --password-file "C:\private\passphrase.txt"
.\best.bat decrypt report.pdf.age --password-file "C:\private\passphrase.txt" -o restored.pdf
.\best.bat verify report.pdf.age --password-file "C:\private\passphrase.txt" --max-bytes 1073741824
```

The password file contains a single UTF-8 line. One final LF or CRLF is removed;
spaces are preserved. Embedded line breaks, NUL, empty passwords, and passwords
over 4096 UTF-8 bytes are refused. New encryption passwords require at least 12
characters; choose a much longer randomly generated passphrase. Character count
alone does not measure password strength. Existing files encrypted with shorter
passwords can still be decrypted.

Passwords are never command-line values, environment variables, or log output.
Protect password files with your operating system's permissions. The application
does not create or silently change permissions on existing secret files.

`--max-bytes N` caps plaintext size on encrypt, decrypt, and verify. It is useful
when processing files from other people or when disk space is limited. Exit codes:
`0` success, `1` operational failure, `2` invalid arguments, `130` cancellation.

## Cryptography and file safety

- Cryptographic operations use the `age` crate, not a new encryption algorithm.
  age v1 uses authenticated ChaCha20-Poly1305 streaming, a header MAC, and either
  X25519 recipient wrapping or scrypt password wrapping. Every encryption uses
  fresh randomness generated by the library from the OS.
- Password encryption uses scrypt `N=2^18`, `r=8`, `p=1`, approximately 256 MiB
  of KDF memory. Public-key mode does not need this password derivation step.
  Decryption defaults to a maximum factor of 18. Only for a trusted external file
  may `--max-work-factor` raise it to 19 (512 MiB) or 20 (1 GiB).
- A 64 KiB header limit is applied before age parsing. Canonical binary v1
  headers are required. ASCII armor, legacy unterminated stanza encodings, SSH
  keys, plugins, and post-quantum recipients are outside this CLI's supported set.
- Output is written to a random, exclusive temporary file beside its destination.
  On Unix it is mode `0600`; on Windows it has a protected DACL granting access
  only to the object owner and SYSTEM. Permissions are present at creation.
- The complete authentication stream and final tag must succeed before decrypted
  output is published. File data is synchronized, then published without replacing
  anything. Unix additionally synchronizes the containing directory. An existing
  file, directory, hard link, or symlink at the output path cannot be overwritten.
- Regular files only: final-component input symlinks/reparse points, special
  devices, Windows alternate data streams, and ambiguous Windows names are refused.
  Windows opens inputs without write/delete sharing; all platforms also recheck
  input length and modification time. Use files that are not being edited.
- Normal error and cooperative cancellation paths drop temporary files. Passwords
  and application-owned plaintext copy buffers use zeroizing storage. `verify`
  discards plaintext in memory and creates no output file.

See [SECURITY.md](SECURITY.md) for the threat model, crash behavior, and limits.
This is a carefully tested implementation, **not an independently audited or
certified security product**. The underlying age crate is pre-1.0 and its upstream
documentation labels it beta. Review and independent security assessment remain
appropriate before relying on this application for high-value production data.

## Build and validate

```text
cargo build --release --locked
cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --all-targets --locked -- --test-threads=4
cargo test --release --all-targets --locked -- --test-threads=4
cargo test --doc --locked
cargo install cargo-audit --locked
cargo audit
```

Use release builds for real data. The tests include actual production-cost password
encryption; no environment variable, feature flag, or test build can reduce the
shipped encryption work factor. Limiting test concurrency avoids oversubscribing
memory. Property tests run 256 generated cases each by default; set
`PROPTEST_CASES=4096` for a longer run. `TESTING.md` explains the suite and optional
interoperability and fuzzing checks. CI checks Windows, Linux, and macOS.

The existing batch helpers were retained as text under `legacy/`. The active
`xxxx11.bat` now provides a build/check/help menu. `src/deleteMainrs.bat` is a
non-destructive notice so an accidental double-click cannot erase the application.
